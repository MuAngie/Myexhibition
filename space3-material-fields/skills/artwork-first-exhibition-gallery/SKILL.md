# 展品优先的交互式展览

把现场照片与视频转化为可以重新打开的展览记录。作品、展签和现场影像按观看关系组织；全景照片保留光线与空间感受，不承担真实建筑复原。

## 先判断是否适用

只有满足下列多数条件时使用本方法：

- 用户关心作品是否完整、展签能否重读，以及能否找到某个展区的照片或视频。
- 参考资料包含作品、文字说明、局部、全景或现场视频，可按已有分类整理。
- 用户希望保留现场光线与氛围，接受直接使用拍摄的全景作为背景。
- 用户不要求复原真实平面、墙体连接、参观动线、尺度或安装关系。
- 交付重点是目标设备上的浏览、切换、查看和记录感受；按用户指定范围支持桌面或手机。

以下情况不要使用本方法，应改用空间还原流程：

- 用户明确要求重建建筑结构、房间连接、空间尺度或可实际漫游的参观路径。
- 需要通过几何模型复原作品与墙体、距离或装置位置的关系，现场照片无法满足目标。

“保留空间感受”不等于“重建空间结构”。有清晰全景、且用户不要求真实漫游时，采用照片回顾方案即可；用户已明确“不还原空间”时不再询问是否做三维复原。只有重建目标仍不清楚时，才说明方案差异并询问。

## 1. 建立照片清单

先一次性读取全部照片并生成联系表，再决定哪些图片进入浏览序列。按以下角色分类：

| role | 含义 | 默认处理 |
|---|---|---|
| `artwork` | 单件作品或清晰的单件展品照片 | 进入主序列 |
| `room` | 空间全景、墙面远景、转角和人流视角 | 可直接作为本展区背景，并保留完整原图查看入口 |
| `group` | 一张照片内有多件作品 | 有独立单件照片时排除；否则询问是否作为组合观看 |
| `detail` | 局部、材料细节、近距离纹理 | 先保留在对应展区；排除前询问，未明确回复时保留 |
| `label` | 作品签、单元前言、展墙文字 | 分别标注类型，先保留供重读；排除前询问，未明确回复时保留 |
| `video` | 投影、光影或其他现场视频 | 放回对应展区，与照片共同浏览 |
| `duplicate` | 同一作品的重复角度 | 选择最完整、透视最轻、清晰度最高的一张 |

保留一份最小清单：原文件名、展区、角色、方向、是否入选、对应派生图、排除原因。完成后分别核对照片、展签、局部和视频的入选数与页面引用数，不把所有素材统计为作品件数。

### 先询问裁切与取舍

准备裁切照片中的展签、局部、墙面、人影、反光或其他现场信息，或排除独立的展签、局部照片前，集中询问用户：是否需要裁切，以及哪些说明与现场信息要保留。已有明确回复时沿用，不重复询问；仅确认“裁切”不等于确认“排除展签或局部”。

没有明确回复或回复含糊时，先保留完整照片及展签、局部素材，继续做分类、按比例缩小副本和页面浏览。不要把未回复当作同意裁切或排除，也不要因此停下其余工作。

## 2. 确定观看序列

优先沿用用户已有的展区分类和名称，提供可直接进入的展区导航；区内依据现场照片中可见的相邻关系和拍摄顺序排列。无法确定真实顺序时，可按材料、色彩、尺度或视觉重量组织，但要标注这是编辑性排序。

- 本区首张影像应能代表该区内容；作品、全景或单元前言均可按材料选择。
- 同时支持“找到某个展区”和“在区内接着往下看”；不为连续观看而强迫用户从第一张开始。
- 横版与竖版交错时，避免连续出现过多相似轮廓。
- 序号和总数始终可见，让用户知道自己位于序列中的哪里。
- 文件名可作为可靠的识别标签；没有可信作品信息时不要编造标题或作者。

## 3. 按确认结果处理照片

默认按比例保留完整照片。先处理 EXIF 方向，生成网页副本与缩略图，原片保持只读；展签、人影、反光和作品周围的环境按用户确认结果保留。主图和原图查看使用自然宽高比与 `object-fit: contain`；背景和导航缩略图可为布局使用 `cover`，但须提供完整照片查看入口。

只有用户明确同意裁切时，才执行以下裁切细则；裁切目标是准确确定展品边界，并用稳定的安全距离形成完整、可信、比例正确的画面。

- 先处理 EXIF 方向，再计算裁切坐标。
- 先找出每件展品的完整外边界，包括画框、底座、悬挂件、垂下部分、投影和突出结构；不能先凭视觉中心直接画裁切框。
- 一张照片含有多件需要共同保留的展品时，分别确定每件展品的边界，再取所有边界的最小集合外框。需要保留的作品签、局部和现场信息也加入集合外框。
- 在单件边界或集合外框的基础上向四周扩张安全距离，然后把结果限制在原图范围内。原图空间允许时，可先尝试各保留约原图宽高的 `3%–5%`，再按作品形态与现场信息微调；这只是起始参考，不是固定比例。
- 边界和安全距离确定后，只裁掉用户已同意去除的墙面、地面或阴影；要求保留的现场信息纳入构图。展品接近原片边缘、无法再留出安全距离时，保留对应原片边缘。
- 不能切掉轮廓、底座、框边或签名。仅在像素层面勉强保住边缘、但视觉上仍紧贴画面边界，也算裁切失败。
- 同一展区的一组作品应保持相对一致的安全距离尺度，但不要为了统一留白而向内切掉某件作品。
- 依据原作品选择横版、竖版或近方形比例，不要把所有图片塞进同一种卡片。
- 仅去除用户同意裁掉的环境内容；未明确同意排除的展签与局部信息应加入保留边界。
- 轻微反光、阴影和拍摄痕迹可以保留，它们属于现场记忆；明显透视失真影响作品比例时再做四点校正。
- 页面使用图片自然宽高比与 `object-fit: contain`，绝不以 `cover` 二次裁掉边缘。

每次修改裁切后，直接预览派生图片，并在页面主图尺寸下再次检查。只看裁切坐标不算验收。

### 作品信息与标签核对

- 作品签照片既可作为元数据来源，也可在对应展区中供重读；单元前言与展墙文字单独标注，不误当成作品签。是否排除按前面的询问结果决定，未明确回复时保留。
- 先用文件拍摄顺序提出候选对应，再用空间照片中的墙面位置、相邻作品和作品本身照片里可见的小标签交叉确认。
- 标题、艺术家、年份、尺寸、材料和作品类别只按标签可辨内容录入；模糊、缺失或标签未提供的字段保持为空，不使用网络常识补写。
- 同一作品的多个拍摄角度共用同一组信息，但保留各自的照片编号。
- 在页面中标注信息来源的标签照片编号，便于回查。
- 找不到可靠对应标签的作品必须明确显示“暂无对应作品签”，并在交付说明中列出照片编号。
- 当前主图可点击打开沉浸式大图；缩略图或相邻图负责切换，弹层需支持关闭按钮、`Esc` 和焦点返回。

### 沉浸式大图与信息层

大图弹层用于看清作品细节，不应延续主页面的左右栏限制。推荐按以下原则实现：

- 初始状态使用原始照片和 `object-fit: contain`，以完整构图适配视口；打开、关闭和复位都回到这一状态。
- 把整个弹层视口作为图像画布。信息区可以固定叠放在右下或其他非中心位置，但不能永久缩窄放大图的活动范围；图像放大后可延伸到信息区周围，并允许在整屏范围内拖动。
- 放大、缩小、复位按钮与鼠标滚轮操作同一个缩放状态，并设置合理上下限。桌面端可从 `100%–400%` 起步，再按照片分辨率调整。
- 只有放大后才启用拖动。平移边界应结合图像的实际布局偏移计算，保证用户能查看图像各边缘，又不会把图像完全拖出视口。
- 在大图视口内拦截滚轮事件，避免同时切换底层作品；`Esc` 只关闭弹层，`Tab` 仍能正常访问关闭和缩放控件。
- 可提供双击复位，以及 `+`、`-`、`0` 等价键盘入口，但不能用它们替代可见按钮。
- 信息底板可使用带透明度的深色，让被放大的现场照片仍隐约可见。可从约 `70%–80%` 不透明度起步，根据最亮和最复杂的照片检查文字对比度；不必为了透明效果增加模糊滤镜。
- 信息层始终位于图像上方，标题、艺术家、年份、尺寸、材料和来源编号不能因背景变化而难以辨认。

### 裁切过紧时

当用户反馈“裁切太紧”“太极限”或作品贴边时：

- 回到原片重新确认每件展品边界；多件作品重新计算集合外框，再从该外框向外扩张安全距离。不要只凭当前错误裁切框向外猜测。
- 裁切坐标必须限制在原图边界内；当原片本身没有更多空间时，优先保住完整边界，不强求四周等宽留白。
- 默认检查并一致调整同一展区的整组作品，避免只有最明显的一张获得留白；用户明确只指某件作品时除外。
- 逐边检查画框、悬挂件、底座、阴影、突出结构，以及用户要求保留的作品签是否完整。
- 扩张到轮廓周围有稳定呼吸空间即可，不要重新带入大片无信息墙面、地面或相邻展品。
- 重新生成派生图；若沿用原文件名，应刷新资源版本或浏览器缓存，避免误把旧裁切当作新结果。
- 在页面实际主图尺寸下抽查横版、竖版、近方形和小型作品，不要只用缩略图判断。
- 只修改当前要求涉及的展区或作品，不顺带改变其他空间的裁切。

## 4. 页面空间关系

页面应主次清楚、主图完整、切换方便，不需要伪造精确画廊。黑水城式照片回顾可采用以下三层结构：

1. **背景层**：本展区的现场全景，阅读作品与说明时适当压暗，保留现场光线和空间关系。
2. **影像层**：完整显示当前照片或视频；缩略图提供直接选图入口，位置依观看方式选择。
3. **界面层**：展区标题、影像类型、来源编号、当前序号、上一张/下一张、展区导航，以及按需求设置的感受入口。

有合适全景时可提供“只看空间”，暂时收起主图、说明和缩略图，保留返回观看及必要导航；背景被视口裁切时，可打开完整照片。简单白模、抽象背景、两侧悬浮作品或克制的镜头变化仍是可选方案，不作为通用验收条件；不得让用户误以为它们代表真实展厅动线。

### 完整构图观看：适配视口

以整体构图和作品间切换为主时，主图可使用自然比例计算，同时受视口宽高限制：

```js
const ratio = image.naturalWidth / image.naturalHeight;
const maxWidth = Math.min(innerWidth * 0.74, 1200);
const maxHeight = Math.min(innerHeight * 0.74, 1000);
const width = Math.min(maxWidth, maxHeight * ratio);
```

这能让横版尽量利用宽度，竖版尽量利用高度，又不裁掉原图。

### 展签与长图阅读：按宽度展开

当照片包含密集文字，尤其是竖幅展签、单元前言、时间轴，或用户反馈“照片太小”“看文字累”时，优先采用阅读布局。完整照片仍然保留，但不强求它与导航同时塞进一屏；不要只让用户每张都打开大图才能读正文。

- 主图按可用阅读宽度展开，保留自然宽高比；较长照片允许沿页面向下滚动。取消主图及容器的固定视口高度、最大高度限制，避免 `contain` 再把竖图缩回小尺寸。
- 缩窄桌面左侧说明区及栏间留白，把宽度让给照片；主图可设置适合阅读的最大宽度，但按素材清晰度和目标设备判断，不照搬固定像素值。
- 桌面端可让左侧标题、当前序号和上一张/下一张控件随页面滚动保持可见。窄屏采用上下布局，避免固定说明区遮住照片或挤占阅读宽度。
- 缩略图优先放在照片上方，使长图阅读不必先滚到底部才能选图。点击照片仍可打开完整大图，放大及原图入口保留。
- 在主浏览区换图后回到新照片开头，不沿用上一张长图的滚动位置；大图弹层内翻页仍按弹层自身逻辑处理。
- 阅读区的滚轮用于滚动照片，不绑定滚轮换图。背景继续承担氛围，固定工具叠在亮照片上时需有清楚的文字底板。

主图的最小 CSS 关系示例，容器宽度和布局仍由项目决定：

```css
.photo-open { width: 100%; height: auto; }
.photo-open img {
  width: 100%;
  height: auto;
  max-height: none;
  object-fit: contain;
}
```

这是展示尺寸与滚动方式的调整，不代表同意裁切照片。不得为扩大展签而擅自去掉周围现场信息；裁切仍遵循前面的用户确认规则。

## 5. 浏览交互

区内所有切换方式操作同一个影像索引：

- 提供可见且有明确名称的上一张/下一张按钮，左右方向键作为桌面端等价入口。
- 点击缩略图直接选中对应照片或视频；采用两侧相邻图时，点击它们也操作同一个索引。
- 滚轮换图仅在适合的布局中启用，不抢占文字滚动、缩略图滚动、视频操作或原图缩放。
- 切换时同步更新主图、选中缩略图、类型、序号和来源编号；逐作品记录仅在采用该记录层级时同步切换。

过渡动画保持轻量，主图是最清晰的一层，避免动效打断读展签、看细节或播放视频。不要求固定的悬浮、卡片或翻页形式。

### 现场视频

- 与照片放在同一展区，提供能辨认的视频缩略图或海报和播放标识。
- 使用可见的播放控件，由用户主动播放，不自动出声；手机端支持内联播放。
- 切换影像、展区或进入原图查看与纯空间模式时暂停视频，避免后台继续播放。
- 播放失败时显示说明，并提供原始视频的打开或下载入口。

## 6. “我的想法”

根据用户需求选择整场展览、某个展区或某件作品的记录层级，不强制每件作品都配笔记。已有入口与存储方案时沿用。

- 展览级记录可使用页面边缘的“我的感受”入口；展区或作品级入口应明确当前记录对象，可放在对应标题或来源编号附近。
- 展开输入区时避免遮挡主图中心和导航，必要时调整主图位置与大小，保证完整可见。
- 使用稳定的展览 ID、展区 ID 或作品 ID 保存，不把可变目录名作为唯一记录标识。
- 展览级记录在换图时保持不变；展区或作品级记录随对应对象切换，避免串写。
- 静态本地项目可使用 `localStorage`；文案应说明内容只保存在当前浏览器。
- 支持明确的收起按钮与 `Esc`，输入框聚焦时方向键不得触发换图。

逐作品记录的最小数据关系示例（不是必需的记录层级）：

```js
thoughts[artworkId] = textarea.value;
localStorage.setItem('exhibition-artwork-thoughts', JSON.stringify(thoughts));
```

项目已有存储键时沿用，不要因套用本方法而迁移或清空用户已有内容。

## 7. 最小实现结构

在没有既有框架时，静态 HTML、CSS、JavaScript 已足够。只有背景确实需要连续视角变化时再加入本地 Three.js，避免为了“空间感”引入不必要的工程复杂度。

建议保留：

```text
project/
|-- index.html
|-- styles.css
|-- app.js
|-- reference/              # 原始照片，只读
|-- assets/                 # 网页副本、缩略图或经确认的裁切图
|-- tools/                  # 可重复执行的裁切脚本
`-- design-qa.md            # 选图、裁切与交互验收记录
```

不要求为了符合此结构而重构现有项目。所有原图保持只读，网页副本与经确认的裁切结果写入独立目录。

## 8. 验收清单

- 分类、入选照片与视频数量和页面引用一致；展签、局部、全景保留与否符合用户确认，未明确回复时未擅自裁切或排除。
- 每件作品的轮廓、画框或底座完整，横竖比例正确，没有被 CSS 再次裁切。
- 经用户确认裁切的图片安全边距肉眼可见，同组尺度相对一致；未裁切图片不以“去除环境”为验收要求。
- 在目标设备上检查横版、竖版和近方形主图；手机同时检查宽度与高度，主图、展区导航、缩略图和控件不互相遮挡，触摸操作可完成。
- 阅读布局使用实际的文字密集照片验收：正文在主浏览区的常用尺寸下可读，长图能滚动看完、换图回到开头，滚轮不误触换图；主图无横向溢出，固定控件不遮挡文字。手机上受屏宽限制仍难辨的细字，可通过可见的大图缩放或原图入口继续阅读。
- 可直接进入各展区，并能在区内继续浏览；提供“只看空间”时可正常返回。
- 实际启用的按钮、方向键、缩略图、相邻图或滚轮切换得到一致结果，不要求全部交互形式同时存在。
- 当前序号、影像类型、来源编号和选中缩略图在切换后同步正确。
- 视频可主动播放，切换时暂停；播放失败时原片入口有效。
- 当前主图可打开完整大图与经过核对的作品信息；来源照片编号正确，缺失信息没有被猜测补齐。
- 大图弹层默认以完整构图适配视口，并提供有上限的放大、缩小与复位；放大后可在整屏画布拖动查看各边缘，滚轮缩放不触发作品切换。
- 固定信息层不会限制图像的放大范围；半透明底板能透出照片气氛，同时在明暗和纹理差异较大的作品上仍保持文字清晰。
- 感受记录层级与用户需求一致，展览、展区或作品之间不串写，刷新后仍可恢复。
- 展开输入区时作品完整可见；收起、`Esc` 和输入焦点行为正常。
- 通过本地 HTTP 服务测试，无脚本错误、资源加载失败或缓存造成的旧裁切。

## 本项目参考实现

`space3-material-fields` 的 02、03 与 04 区是逐作品观看的参考实例，三区共用交互框架，但分别维护作品清单、数量和观看序列：

- `index.html`：02 的十二件作品、03 的十四件作品、04 的十三件作品，以及三套独立顺序的语义结构。
- `styles.css`：自然比例主图、两侧悬浮作品、展品下方的想法入口与展开布局。
- `app.js`：统一作品索引、滚轮/点击/键盘切换、背景镜头变化和逐作品本地笔记。
- `tools/prepare_assets.py`：从原始现场照片生成独立 Web 裁切图；修改可复现的裁切坐标后重新生成，不直接覆盖原图。
- `design-qa.md`：照片筛选、裁切和交互验收记录。

[黑水城](../../../space5-heishui/README.md)是照片回顾的参考实例：现场全景背景、按现有分类进入五个分区、主图与底部缩略图、展签原图缩放、对应展区中的视频、纯空间观看和展览级感受记录。查看其 `data.js`、`index.html`、`app.js` 与 `styles.css` 理解这些关系，不照搬固定分区数或布局尺寸。

复用时借用决策逻辑，不要照搬现有作品件数、尺寸数值、颜色或文件名。新展览仍需根据自身素材建立清单，只有用户明确同意裁切时才建立裁切边界。
