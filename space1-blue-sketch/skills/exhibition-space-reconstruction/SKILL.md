# 展览空间照片还原

把一组不完整、视角不一致的现场照片转化为可信的互动空间记忆。本方法以空间感受为核心，优先还原参观者能识别的尺度变化、空间关系、行进节奏、材料、光线以及作品与场所的联系，不把摄影推断伪装成精确测绘。

## 适用边界

这是“空间优先”的复原方法。空间必须具有值得被单独还原的辨识度，并且不是可以随意替换的作品背景。

适合使用的情况：

- 房间的高低、开合、转折、入口或行进路径会改变观看感受。
- 墙面、地面、天花、自然光或人工照明具有明显的材料与氛围特征。
- 大型装置、雕塑、影像或声音与所在位置不可分割。
- 用户希望重新体验“走进这个展览”的感觉，而不只是逐件翻看作品。
- 用户会依据现场照片检查平面关系、墙体位置、视线和作品的相对陈列。

不适合使用的情况：

- 展厅只是中性容器，换成简单白模也不会损失主要体验。
- 用户的重点是单幅作品是否完整、裁切是否正确、切换是否顺畅。
- 参考资料以单件作品照片为主，空间照片只承担背景说明。
- 交付目标更接近连续作品浏览、个人收藏或观后感记录。

遇到后一类需求，应改用 `artwork-first-exhibition-gallery` 的“展品优先”方法。不要为了形式上的 3D 漫游虚构复杂空间，也不要把真正依赖场所关系的展览降级为普通作品轮播。

## 先确定还原目标

在建模前明确以下边界；能从现有材料判断时直接说明假设，不为低风险细节反复追问：

- 交付形式：单个 HTML、前端项目、视频，或仅空间方案。
- 精度类型：氛围还原、视觉近似、陈列顺序准确，或有尺寸数据支撑的几何还原。
- 设备范围：桌面鼠标键盘、移动触摸，或两者。
- 交互范围：漫游、点击靠近、查看原图、信息标签、动效。
- 资产边界：是否保留照片中的外框、反光、墙面纹理和拍摄透视。
- 文件范围：只在用户指定目录内工作，不默认安装依赖、发布网站或修改外部文件。

将证据分成三类并在实现中保持区别：

1. **照片明确显示**：作品顺序、墙色、地板方向、隔墙、轨道灯等。
2. **多张照片共同推断**：墙体连接、转角位置、通道宽度、拍摄方向。
3. **为体验补全**：看不到的墙面、灯光强度、碰撞边界、空气粒子等。

不要用第三类内容反向声称空间完全准确。

## 1. 建立照片清单

先读取所有照片，不要一张一张边看边建模。

- 读取 EXIF 方向后再分析尺寸、裁切和透视；否则坐标会错位。
- 生成联系表或缩略图网格，快速识别重复视角和空间连续性。
- 将照片分为：空间全景、墙面序列、单幅作品、组合画面、文字/标识、材质/灯具、雕塑或其他物件。
- 为每张图记录：文件名、角色、可能所属墙面、朝向、可见相邻物、是否需要裁切/透视校正、置信度。
- 单独统计“单幅作品照片”，并建立一份作品资产清单。最终必须逐项核对是否都进入空间。

推荐使用如下最小清单字段：

| source | role | wall/zone | neighbors | correction | confidence |
|---|---|---|---|---|---|
| 原始文件名 | overview/artwork/detail | 暂定位置 | 左右相邻线索 | crop/perspective/none | high/medium/low |

## 2. 推断空间拓扑，而不是先猜尺寸

先画出“哪些墙和通道相连”，再决定具体米数。

- 以入口为原点，固定坐标方向；例如前后使用 Z、左右使用 X、高度使用 Y。
- 利用重复出现的作品、隔墙边缘、轨道灯、踢脚线、地板拼缝和天花梁连接不同照片。
- 优先确认：外围墙、尽端墙、隔墙、入口/通道、不可穿越区域、作品排列顺序。
- 用画框、门洞、灯轨间距等重复物体估计相对比例；没有可靠参照时只求内部一致。
- 建立关键视点：入口、主要墙面正视、隔墙两侧、尽端回望。后续都用这些视点验收。

如果照片之间存在冲突，保留最能解释多数视角的拓扑，并记录不确定处。不要为填满空间而增加照片中没有证据的结构。

## 3. 处理作品资产

作品纹理质量直接决定还原是否可信。空间建模与作品裁切分开处理。

### 普通裁切

- 先执行 EXIF 方向归一化。
- 以真实外框外沿为裁切边界；需要保留画框时，不要只裁画芯。
- 去掉画框上下左右的墙面。墙面一旦留在纹理里，3D 平面会按错误的整图宽高比生成异常框幅。
- 裁完立即检查像素尺寸和宽高比，再直接预览成品，不只看裁切坐标。
- 保留用户明确要求的外框、少量反光或现场痕迹；不要擅自“修复”为无菌扫描图。

### 透视校正

只有当四个真实外框角可可靠识别、且斜拍明显影响比例时，才使用四点透视变换。

- 四点顺序保持一致：左上、右上、右下、左下。
- 目标宽高比参考真实外框，而不是随意拉成常用纸张比例。
- 变换后检查黑边、被拉伸的边框和裁掉的签名。
- 轻微斜拍可以保留；过度校正会抹掉现场感并制造错误比例。

### 组合照片

一张照片包含多幅作品时，可分别裁出独立资产。分割后仍要在清单中保留它们与原组合图的关系，以便恢复正确顺序和间距。

### 输出

- 原始照片只读保存，派生资产写入独立目录。
- Web 纹理使用合理尺寸和压缩，优先保证作品细节，不把所有照片无条件放大。
- 3D 画面尺寸使用纹理自然宽高比：`height = width / imageAspect`。
- 完成后执行清单对账：源作品数、派生资产数、场景引用数应能解释彼此差异。

## 4. 分层搭建空间

按以下顺序推进，每一层通过关键视点后再进入下一层：

1. **灰盒几何**：地面、外围墙、尽端墙、隔墙和通道。
2. **作品挂放**：先顺序和中心高度，再调整尺寸与间距。
3. **结构细节**：天花、梁、灯轨、踢脚线、展台。
4. **材质与光线**：墙色、木地板、粗糙度、轨道灯和曝光。
5. **氛围与界面**：雾、微尘、暗角、标题和控制提示。

艺术品应是场景中最清晰、最亮但不过曝的信息层。装饰性动效不能抢过作品，也不能掩盖空间比例问题。

## 5. 校准颜色、纹理与灯光

不要从单张照片直接吸取一个墙色作为最终值；相机白平衡、曝光和灯光会显著改变颜色。

- 对比多张不同角度照片，找出在明暗区域都成立的墙色范围。
- 将“墙体固有色”和“灯光造成的偏色”分开：材质决定基色，灯光决定局部暖冷。
- 墙面纹理用低对比、低频细节表达；不要把噪点做成星空或污渍。
- 地板方向应与空间透视一致，粗糙度和反射保持克制。
- 轨道灯数量、方向和光斑位置比纯粹增加环境亮度更能恢复现场感。
- 每次只调整一类变量：先墙色，再曝光，再灯光色温，避免互相抵消后无法判断。

颜色验收以“多张参考照片共同呈现的氛围”为准，不以某一像素值为准。

## 6. 桌面端漫游与作品交互

当用户没有指定框架时，可优先使用本地 Three.js 和静态 HTML，避免网络依赖导致本地文件无法运行。若项目已有技术栈，则沿用现有结构。

### 漫游

- 鼠标拖拽控制水平和垂直视角；垂直方向要通过实操确认，不能只凭代码符号判断。
- 滚轮负责前进/后退，并明确验证“向上/向下”各自语义。
- WASD 或方向键作为桌面端备用移动方式。
- 限制俯仰角，防止翻转；为墙体和隔墙设置简单碰撞，避免穿墙。
- 控制提示保持简短，进入后让界面退居次要位置。

### 作品点击状态

推荐使用明确的两阶段状态，而不是依赖浏览器双击事件：

1. 第一次点击当前作品：将相机平滑移动到正面观看位置。
2. 再次点击同一作品：打开无透视变形的大图查看层。

实现时记录当前已聚焦作品。手动拖拽、滚轮、键盘移动或回到入口后，清空聚焦状态。悬停文案应随状态显示“点击靠近”或“再次点击查看原图”。

大图查看层至少支持关闭按钮、点击背景和 `Esc`；打开时暂停移动按键。显示派生的正视作品资产，而不是带 3D 透视的画布截图。

点击命中应使用当前指针坐标，不依赖上一次 `pointermove` 留下的旧坐标。点击距离阈值要覆盖正常观看距离，但不要隔墙选中远处作品。

## 7. 浏览器验收

不要以“文件已生成”作为完成标准。至少执行以下闭环：

- 通过本地 HTTP 服务打开页面，确认本地脚本和纹理可加载。
- 入口页进入正常，首帧没有黑屏或阻塞式加载。
- 从关键视点截图，与参考照片比较墙面顺序、隔墙位置、作品排列和氛围。
- 逐项检查作品清单；特别关注画框宽高比、被裁切边缘和重复/遗漏作品。
- 实操拖拽上下方向、滚轮前后方向、WASD、碰撞和回到入口。
- 对同一作品完成“点击靠近 → 再次点击看原图 → 三种方式关闭”。
- 检查浏览器错误、失败资源和异常长宽比。
- 修改图片但复用同一文件名时强制刷新；只有确认缓存干扰时才增加版本参数。
- 在用户指定的目标设备尺寸上复测；桌面限定项目不要擅自追加移动端触摸逻辑。

## 高价值失败模式

### 画框变成异常竖幅或横幅

最常见原因不是 3D 几何，而是纹理仍包含大片墙面，或 EXIF 方向未归一化。先直接预览派生图片并检查自然宽高比，再动场景尺寸。

### 空间“像蓝色画廊”，但不像参考照片

原因通常是只匹配了色相，没有同时匹配明度、粗糙度、局部暖光、天花暗部和地板反射。按材质与光照分层校准。

### 单幅照片很多，但场景仍缺作品

原因是没有建立资产清单和场景引用对账。不要凭视觉印象判断“应该都放上了”。

### 点击偶尔无效或第二次点错作品

检查指针坐标是否在 `pointerdown` 时更新、相机移动后射线是否重新计算，以及手动漫游时是否正确重置聚焦状态。

### 过分追求几何精度

没有测量数据时，增加小数位不会增加真实性。把精力放在拓扑、视线、作品顺序、相对比例和光线层级上，并清楚标注推断范围。

## 建议交付结构

```text
project/
|-- index.html
|-- PRODUCT.md                 # 体验目标、范围与审美原则
|-- reference/                 # 原始照片，只读
|-- assets/artworks/           # 裁切或校正后的作品纹理
|-- tools/                     # 可重复执行的资产处理脚本
`-- vendor/                    # 本地运行所需的前端依赖
```

目录可按现有项目调整；不要为了匹配模板重构用户已有工程。

## 完成标准

只有同时满足以下条件才算完成：

- 关键视点能让参观者认出原空间，而非只认出相似配色。
- 作品顺序、数量和画框比例已通过清单核对。
- 墙色、墙面质感、地板、天花与灯光共同接近参考氛围。
- 桌面端控制方向经实操确认，碰撞没有明显穿墙。
- 作品的两阶段点击和大图关闭流程可完成。
- 页面离线或按用户要求的运行方式可正常加载。
- 已说明照片无法确定的部分，没有声称工程级精确还原。
